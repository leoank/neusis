## Question
kalam-zero is a kalam flavour published as a single `init.lua` for machines without Nix
(Neovim 0.8+, `NVIM_APPNAME=kalam`). Can that file be generated by nixvim from the same
modules as kalam, rather than written by hand?

## Hypothesis and predictions
H1: with the right nixvim options, `config.build.initFile` contains no `/nix/store`
paths and no Nix-wrapper assumptions, and loads in a plain Neovim. If true, the zero
flavour reuses base's `keymaps.nix` directly; if false, it is a hand-written Lua file
with keymaps generated from Nix.

## Plan
1. Build base's keymaps with no plugins on nixvim's defaults; list what isn't portable.
2. Find the options that remove it; rebuild and load the result in headless nvim.
3. Repeat step 2 on Neovim 0.8–0.11 release builds.

## Success criteria
The generated file has no `/nix/store` path, no `vim.loader` call and no runtimepath
edit, and loads without error with its keymaps set on every supported Neovim.

## Runs
One line per run after its link, what was tried and what it showed; `yajna validate`
rejects a bare link here. Metric runs also land in results.tsv.
- [[RUN-20261103-g9nmnp]] defaults leak 2 store paths and 2 runtimepath edits; five options remove them, and the result loads cleanly in nvim 0.12.4
