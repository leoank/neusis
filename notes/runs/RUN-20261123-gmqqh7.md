## Notes
Two builds of a one-line C program (differing by one string) signed by rcodesign 0.29.0
with a throwaway self-signed code-signing certificate from a PEM file, no keychain, and
the identifier `dev.leoank.sigtest`. Both carry the same embedded designated requirement,
`identifier "dev.leoank.sigtest" and certificate root = H"<cert sha1>"`, with no cdhash;
build 2 satisfies build 1's requirement and an ad-hoc build does not; `codesign --verify
--strict` accepts both and both run. Full output in `results.txt`.

This run is the scripted repeat of a hand probe earlier the same day (same steps, typed
into a shell; it gave the same answers with another throwaway certificate). That probe
also found that rcodesign only adds a designated requirement by itself for Apple-issued
certificates, per its `--help`, yet it did embed one here; and that supplying one through
`csreq` is therefore unnecessary (that attempt was dropped after a syntax slip, untried).

## Reproduce
Run `script` from the repo root in the project's dev shell at `commit`; it must produce the
same outputs. Note here what it cannot control.

Needs macOS (`/usr/bin/cc`, `codesign`). rcodesign and openssl come from the nixpkgs rev in
`flake.lock`. The certificate is new on each run, so the hash in the requirement, and so
`results.txt`'s hash, differs every time; the yes/no lines are what must match. What this
does not test: whether TCC keeps a real grant (Input Monitoring, Local Network, App
Management) across a rebuild, and signing an app bundle with nested frameworks (kitty.app).
