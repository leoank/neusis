## Introduction
neusis is the flake that configures Ank's machines and the library other fleet repos
build on: NixOS, nix-darwin and home-manager modules, opt-in feature bundles, per-user
home bundles, registries of machines, users, builders and deploy groups, agenix-rekey
secrets, terranix stacks for the cloud hosts, and the `neusis` Go CLI that scaffolds
consumer repos and deploys cloud machines. It is written here rather than taken off the
shelf because the fleet spans macOS and Linux, a lab mesh and cloud hosts, and no
existing config library covers that with per-user opt-in and one test ladder.

Until 2026-11-03 the engineering record was `docs/porting.md`; it is frozen as history
and this notebook, `docs/architecture.md` and `docs/decisions/` carry on from there.

## Design
The architecture is `docs/architecture.md` and its decision records are
`docs/decisions/`; here, only the few choices
a reader must know before touching the code.

- `flake.nix` is generated by flake-file: declare inputs next to the code that uses them and run `nix run .#write-flake`.
- Every `.nix` under `modules/` is a flake-parts module picked up by import-tree; a `_` prefix keeps a file or directory out.
- Agnostic system modules dispatch on `options ? systemd` / `options ? launchd`, never on `mkIf` over a platform attribute.
- Features are opt-in per user or per machine, never forced through shared defaults.

## Lessons
What was tried and dropped, and why, so nobody tries it again.

- Several `tailscaled` daemons for concurrent tailnets: Linux-only and breaks exit nodes; an application-level proxy (`docs/tailmux-proxy-spec.md`) is the path instead.
- beads (`bd`) for agent task tracking: used too little to earn its hooks; removed 2026-10-06 and 2026-11-03.
- The pre-2026-11-03 gotchas, with their rationale, are in `docs/porting.md` (*The single most important rule*, *Other gotchas worth memorizing*).
